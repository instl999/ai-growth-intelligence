# 文章版式与写作规范

简报要写成**一篇完整的文章**，不是一份条目清单。参照的是中文科技公众号的日报体例：标题由当天几条头条组成，开头一个速览目录，然后每条单独成篇、分段叙述，来源写进句子里。

## 整篇的结构

```
# {头条一}/{头条二}/{头条三}          ← 标题就是当天最重要的几条

AI 成长情报 · 9月17日 · 今天 10 条    ← 落款行

- 💻 {标题}                           ← 速览：每条一行，带分类图标
- 💻 {标题}
- 🧠 {标题}
...

## GitHub 精选                        ← 版块名，不带条数

### {标题}                            ← 正文标题：普通一句话，不编号

{第一段：据某某报道，发生了什么。}

{第二段：背景或细节，带数字。}

{第三段：这对读者意味着什么。}

{第四段：可以怎么做。}

🧰 {工具名}｜{功能}｜场景：…｜价格：…｜官网   ← 仅 AI 工具类

🔗 {来源链接}
```

速览目录是整篇最重要的一块：读者先一眼扫完今天有什么，再决定跳进哪几条。

## 每条怎么写

**正文写在 `body` 里，是一个段落数组。** 这是新版和旧版最实质的区别：旧版把 `whyItMatters`、`whatHappened`、`personalImpact` 三个字段拼成固定的一段，渲染器再怎么调整，产出的都只能是一张卡片。文章需要由写的人决定哪里分段，所以分段权交回给你。

写 `body` 的要求：

- **2 到 5 段**，每段 1 到 3 句。段落之间留白，不要写成一大块。
- **第一段交代来源和事实**：「据界面新闻 9 月 17 日报道，……」「官方博客发布的说明显示，……」。来源写进句子里，这是公众号的常规写法，也让读者不用跳到末尾才知道消息哪来的。
- **中间段落给背景、数字、对比**。具体的数字比形容词有用：准确率 97.3%、本周新增 4300 star、降幅约 60%。
- **倒数第二段落到读者身上**：这件事改变了什么，谁会受影响。
- **最后一段说可以怎么做**，写成正常的句子，不要加「上手：」这类标签。
- 全程第二人称和口语，短句优先。

`body` 没写时，版式会退回用三个旧字段拼出三段——仍然是分段的散文，但远不如自己写的好。**默认就应该写 `body`。**

## 字段速查

| 字段 | 位置 | 要求 |
| --- | --- | --- |
| `headline` | 标题、速览、正文标题 | 说结果不说公告，26 字以内；标题栏最多放三条，太长会自动减为两条 |
| `body` | 正文 | 2–5 段散文，来源写进句子 |
| `icon` | 速览行首 | 可选，覆盖分类默认图标；只用单码位表情 |
| `actions` | 末段 | 仍然必填，没写 `body` 时作为最后一段 |
| `tool` | 🧰 行 | 仅 AI 工具类，功能、场景、价格、官网四项齐全 |
| `sources` | 🔗 行 | 必填，正文里也要提到出处 |

分类图标：`💻` GitHub、`🧠` AI、`🧩` Skill、`💵` 商业财经、`💡` 成长。**只用单个码位的表情**，像 `🧑‍💻` 这种 ZWJ 组合在字体缺字时会退化成半个图标。

## 不要出现的东西

- 任何「字段名＋冒号」的写法：`为什么值得关注：`、`项目情况：`、`建议行动：`、`来源：`、`上手：`。
- 条目编号（`01 ｜`）、条间分隔线、`🔥 今日更新` 这类角标——这些都是卡片清单的零件，文章里不用。
- 版块标题里的条数和时间窗说明。这些是运维信息，仍然保留在 `article.sections` 里。
- 开头讲筛选过程：「经过验证」「候选池」「未达门槛已省略」「共筛选 X 条」。开头是落款行加速览目录，不是流程说明。

## 切换回旧版式

```json
{ "article": { "style": "brief" } }
```

`article`（默认）是上面的文章版式，`brief` 是每行一个粗体标签的最初版式。取值无法识别时回退到 `article`。

发送前先看排版：

```
node src/cli/index.js preview-article --config config.json --items items.json --markdown
```

## 公众号渲染

`src/wechat/html.js` 按行首标记决定样式：`🧰` 是浅灰描边的工具块，`🔗` 是小号灰字，`- ` 开头且不以 `**` 开头的是速览行（紧凑无边框）。标记定义在 `src/core/article-composer.js` 的 `LINE_MARKERS`，两边共用同一份常量。文章版式的 HTML 比最初版式短约两成，因为不再重复标签，公众号两万字符上限也更宽松。
