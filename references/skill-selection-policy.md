# Skill selection policy

## Priority discovery sources

Scan these sources independently in every research window; they are priority sources, not an exclusive allowlist:

- ClawHub — `https://clawhub.ai/`
- SkillHub — `https://skillhub.cn/`
- skills.sh — `https://www.skills.sh/`
- SkillsMP — `https://skillsmp.com/`
- GitHub Skill repositories — `https://github.com/`

Also retain broad discovery through creator sites and official ecosystem directories when they meet the same standards.

SkillsMP is an independent community index of public GitHub `SKILL.md` files. Use its search, creator, occupation, popularity, classification, and update metadata only for discovery. It does not certify safety or quality; always follow a retained result to its GitHub source and verify it under the rules below.

## GitHub Skill discovery

- Search specifically for repositories containing installable `SKILL.md` files, explicit Skill directories, Agent Skill collections, or release notes for Skills.
- Require clear repository ownership or provenance, usable installation instructions, and sufficient documentation to understand permissions and dependencies.
- Route an installable Skill package to `Skill 精选`. Route a general tool, framework, library, model, or code project to `GitHub 精选`.
- Never include the same repository in both sections during the same briefing. Deduplicate by canonical repository and source URL before section counting.

## Verification workflow

1. Search each priority source for new, updated, trending, featured, and official Skills relevant to the operator interest profile.
2. Open the individual Skill page or GitHub repository. Record name, creator, description, version or update signal, source URL, installation route, and any visible trust or usage signals.
3. Trace directory listings to the creator's repository or official documentation whenever available. Use first-party material to verify functions, requirements, permissions, installation, maintenance, license, and security-sensitive behavior.
4. Treat rankings, downloads, stars, platform badges, classifications, indexed counts, update timestamps, and descriptions as discovery signals only. They do not prove that a Skill is useful, safe, maintained, or compatible.
5. Reject duplicates, copied listings without clear provenance, unsupported marketing claims, stale or undocumented packages, and Skills whose practical value cannot be explained.
6. Apply the same value threshold, interest profile, source rules, and five-item section minimum used by the rest of the briefing.

## Output requirements

For every retained Skill, provide a compact title, why it matters, current Skill situation, a concrete action, the discovery URL, and the creator repository or official documentation URL when available. Clearly distinguish platform metadata from verified creator claims.
